# 场景业务建模

用户已确认采用三套轻量业务模型，保留静态 HTML 和现有视觉风格。

- 场景卡片只展示用途、关注指标和部署基线；输入输出全部在配置建议中。
- Coding：开发者数 × 每人每小时任务数 ÷ 60，乘每任务调用数，计算调用 RPM 及输入、输出 TPS。支持生成、Agent、补全预设，吞吐优先，同时约束首字、输出节奏和任务完成时间。
- 聊天：高峰每分钟新会话 × 每会话问答轮数，作为稳态高峰请求 RPM；一次问答默认一次模型调用。首字 p99 与 TPOT avg 为约束。
- ChatBI：每分钟问题 × 每问题调用数，首字 p99 和平均任务完成预算为约束。SQL 执行等外部耗时单独作为用户假设，未提供实测。
- 所有场景可编辑每次调用平均输入、输出 tokens；多步骤按相同平均负载及串行调用粗估，缓存收益、重试、排队变化未计。
- 数据绑定模型、卡型和输入输出长度。负载不一致时只计算需求，禁止输出推荐设备数和业务容量。匹配时仍标为参考估算或 Mock，不视为业务 SLA 保证。
- Coding Mock 用 8192 / 1024 tokens，聊天及 ChatBI 引用已有 3069 / 512 实测；原始实测不改动。
- 推荐：先筛时延约束，再取单套调用吞吐最高点；另列最低首字与最高吞吐点，显示约束满足情况。无达标点、无数据、负载不匹配均有明确状态。
- 配置卡片直接展示估算套数、设备数量与总容量，不再提供配置倍数。步骤 2 为响应目标和场景体验，步骤 3 比较配置；体验方案选择器与卡片双向联动。Coding 展示 TypeScript、聊天展示客服对话、ChatBI 展示未执行的 SQL 示例。回放始终注明引用基线，负载不匹配时不推算业务规模。
- 验证：Node 内建测试覆盖容量和推荐边界，浏览器验证三场景、预设切换、输入编辑、无数据、回放与窄屏。

- 每个场景步骤 1 均展示业务负载长度、需求输入 / 输出 / 总 TPS 和模型 QPS；步骤 2 展示对应压测负载下的单套输入 / 输出 / 总 TPS、QPS、单请求 Decode TPS，继续展示 TTFT / TPOT。共享压测目录按精确长度匹配；不匹配时明确参考口径，无数据则显示待测。
